svgo.mbt is an SVG optimizer written in MoonBit and compiled to one wasm-gc module. Same plugin pipeline as svgo's preset-default, a fraction of the runtime: it runs in the browser, in Node 22+, or as a 1 MB native binary, and every optimisation is checked with pixel diffs before it ships.

Same pipeline, one fifth of the time.

Measured in one Node process against svgo 4.1, both with multipass, on real editor exports and the classic large test files. The MoonBit side pays for JSON serialisation of the result; the JS side is warm. Numbers regenerate from packages/compare/collect.mjs.

Where svgo-js wins it is through inlineStyles/minifyStyles, which need a CSS parser and are on the roadmap.

Every optimisation is a value.

A plugin is { name, description, run }. The preset is an array literal in svgo's order, the CLI and the playground list it, and each one reports whether it changed the tree so multipass knows when to stop. 25 plugins ship today.

Three ways in, one codebase.

The wasm build is the primary artifact. The same source also produces a native CLI and a MoonBit library you can embed in your own tooling.

JavaScript · npm

Node 22+, Chrome 130+, Firefox 134+, Safari 18.4+ (JS String Builtins).
import { optimize } from "svgo-mbt";

const r = await optimize(svg, { precision: 3 });
r.data          // optimized SVG
r.originalSize  // 836
r.size          // 276
r.applied       // ["convertPathData", ...]

Command line · native

A single binary; cold start is about 40× faster than the svgo CLI.
svgo icon.svg --stats
svgo icon.svg -o out.svg -p 2 --pretty
svgo icon.svg --json | jq .size
svgo icon.svg --plugins convertPathData,sortAttrs
svgo --list

MoonBit · library

Plain structs, no globals; parse, plugins and path packages are usable on their own.
let r = @svgo.optimize(svg, config={
  ..@svgo.Config::default(),
  precision: 2,
})
r.saved_percent()  // 67.0

// or just the path optimizer
@path.optimize_string("M 0,0 L 10,10")  // "M0 0l10 10"

Verified, not just smaller.

Every fixture is rasterised before and after with resvg and compared pixel by pixel. Plugin behaviour is locked in svgo-style fixture files, performance changes must reproduce the corpus byte for byte, and moon test runs on wasm-gc, JS and native. Left: editor export. Right: svgo.mbt output.
